# n8n → Claude prompt: build a Stayful web‑meeting presentation

Paste the block below into your n8n Claude node as the prompt. Provide the
reference deck (`sunil-m6-webmeeting.html`) as `{{REFERENCE_HTML}}` and the
lead's extracted data as `{{LEAD_DATA_JSON}}`. Claude returns the finished,
personalised HTML for that lead.

> The reference deck already contains a complete voice‑command engine, all
> interactive sections, styling and scripts. The model must **reuse it verbatim
> and only swap the lead's data** — never regenerate the structure or the
> `<script>`/`<style>` blocks from scratch.

---

## PROMPT

You are generating a personalised **Stayful web‑meeting presentation** — one
self‑contained HTML file — for a single property‑owner lead.

You are given:
1. `REFERENCE_HTML` — the complete, working reference deck. This is your base.
2. `LEAD_DATA` — JSON with this lead's figures and content.

Your job: output the **full HTML** for this lead by inserting their data into the
reference deck. **Preserve everything else exactly.**

### Hard rules (do not break these)
- Output the **complete HTML file and nothing else** — no markdown fences, no
  explanation, no comments about what you changed.
- **Do not modify** the `<style>` block, the `<script>` block, the voice‑command
  controller, the PDF overlay, or the mechanics of any `data-cue`, `data-cue-nav`,
  `data-cue-target`, `data-cue-class`, `data-cue-click`, `data-cue-pdf`,
  `data-cue-city` or `data-cue-label` attribute. These power the voice system and
  must stay byte‑for‑byte identical.
- **Do not add, remove or reorder slides or interactive sections.** Every button,
  dropdown, tab and overlay in the reference must remain.
- Only change **visible lead‑specific text and numbers**, and the values inside the
  `ST:…` token markers (keep the `ST:` comment markers themselves in place).
- All figures must be **internally consistent** — use the Calculations section.
- Keep British formatting: `£`, thousands separators (`£18,672`), `%`.

### LEAD_DATA fields (provided by n8n)
- `owner_first_name` — e.g. "Sunil"
- `property_address` — full address string used throughout
- `net_monthly`, `net_annual` — Stayful net (after all fees), £ per month / year
- `ltl_monthly` — long‑let net, £ per month  (drives `ST:LTL_MONTHLY`)
- `nightly_rate`, `occupancy_pct`, `market_occupancy_pct`
- `bedrooms`, `sleeps`
- `forecast_12` — array of 12 integers, net £ per month Jan→Dec (drives `ST:FORECAST`)
- `comparables` — list of {name, dist_km, nightly, occ_pct, annual, rating, is_top}
  (drives the `ST:BLOCK …COMP_ROWS` table)
- `comp_avg` — {rating, reviews, nightly, occupancy_pct, annual_revenue}  (market band)
- `reviews_to_competitive` — e.g. "6–10 months"; `reviews_avg` — e.g. 19
- `top10_net_annual`, `top10_net_monthly`, `top_performer_gross` — top‑10% outlook
- `amenities` — {baseline:[], edge:[], gap:[]}  (drives the AMENITY blocks)
- `demand_drivers` — list of {icon, tag, title, count_label, location, distance_km, demand_level}
  (drives `ST:BLOCK …DEMAND_DRIVER_CARDS`)
- `direct_booking_score` — 0–100 (drives `ST:DBSCORE`)
- `events_nearby` — integer (drives `ST:EVENTS_NEARBY`)
- `risk_worst`, `risk_likely`, `risk_best` — monthly net £ for the risk chart
- `calendar_url` — this property's Uplisting calendar link
- `slack_url` — this property's Slack channel link
- `meeting_date`, `source_line`
- Lead‑context (Notes slide): `profile`, `phone`, `mortgage_note`, etc.

> Case‑study PDF links (Manchester / York / Leeds) and the income‑statement Drive
> link are **fixed Stayful assets** — leave them exactly as in the reference.

### Calculations (compute, do not ask)
- **Gross monthly** = round(`net_monthly` ÷ 0.52)  (equivalently net + 92.3%)
- **Gross annual** = Gross monthly × 12
- **Property cost breakdown** (share of gross): platform fees **15%**, cleaning
  **18%**, property management **15%**, total **48%** — give annual + monthly each.
- **Short‑let vs long‑let box**: annual = `net_annual` − (`ltl_monthly`×12);
  monthly = `net_monthly` − `ltl_monthly`. If positive use the green "up" styling
  (`pf-verdict-up`), if negative the amber "down" styling (`pf-verdict-down`), and
  show the `%` vs long‑let.
- **Quietest / peak month**: min and max of `forecast_12`, with their £ delta vs
  `ltl_monthly`.
- **Management‑charges waterfall** (How Stayful works → "15% + VAT" dropdown,
  `ST:CH_*` tokens): Gross → −15% online platform fees → after‑platform subtotal
  → −15% Stayful management (of the subtotal) → **your net**. Annual + monthly.
  (Cleaning is NOT deducted here — it's guest‑paid.)
- Long‑let annual = `ltl_monthly` × 12.

### Where the data goes (by slide)
1. **Notes** (presenter prep) — lead‑context fields. The "Voice commands" list is
   auto‑generated by script; leave it untouched.
2. **Property** (cover, centred) — title + subtitle with owner name & address; the
   paired boxes Gross (annual/monthly), Net (annual/monthly), Nightly rate /
   Occupancy, Long‑let (annual/monthly), the short‑let‑vs‑long‑let verdict box; the
   "Cost breakdown" button reveals the platform/cleaning/management split.
3. **The Numbers** (centred) — header line with the £/mo average and delta vs
   long‑let; the 12‑month chart (`ST:FORECAST`, `ST:LTL_MONTHLY`); quietest/peak
   month cells; "View competition" → market band (`comp_avg`) + comparables table
   (`COMP_ROWS`); "Your path to the top" → milestone timeline, the catch‑up/top‑10%
   outlook cards, the **review‑velocity** comparison (keep the fixed messaging:
   Stayful 1‑in‑2‑3 stays → a review vs typical 1‑in‑4‑8), and the amenity gap.
4. **Investment Returns** — best/likely/worst scenario figures; the centred,
   collapsible **risk profile** chart (verdict shown at the top: long‑let vs
   short‑let decision from `risk_likely` vs `ltl_monthly`); the three case‑study
   cards (fixed) + the Uplisting card.
5. **Who Books** (centred) — demand‑driver cards (`DEMAND_DRIVER_CARDS`) + the
   Events card (`ST:EVENTS_NEARBY`); "View direct booking score" → score /100
   (`ST:DBSCORE`) with meter; "How Stayful gets direct bookings" → the lead‑focused
   benefits (30%+ direct, lower platform/cleaning/maintenance costs — keep wording).
6. **How Stayful works** — model‑strip buttons (Management charges, Cleaning,
   Contract, Compliance) each opening their dropdown; the 3‑tab hub (Guest vetting,
   Onboarding, Management) with the live‑tool tiles using `calendar_url` / `slack_url`.

### Features that must remain (this is the standard deck — keep all of it)
- **Voice‑command engine** (active with `?present=1`): keyword section reveals,
  slide navigation by title/alias, spotlight focus‑and‑fade, close‑and‑reopen of
  dropdowns, "next/previous slide", "close"/"reset", and the case‑study PDF overlay.
  Every section/slide carries `data-cue*` attributes — keep them all.
- The **auto‑generated voice‑command reference** in the Notes slide (script‑built).
- Expandable dropdowns: Cost breakdown, Management charges, Cleaning, Contract,
  Compliance, Direct booking score, Direct booking process.
- The PDF overlay for case studies; the centred + collapsible risk profile.

### OUTPUT
Return only the finished HTML document for this lead.

## Notes for maintaining this

- The single source of truth is **`sunil-m6-webmeeting.html`**. When you change the
  deck (new section, new voice command, restyle), update that file, then your n8n
  flow automatically inherits it because the prompt says "reuse the reference and
  only swap data".
- New voice commands need **no prompt changes** — they're plain `data-cue` /
  `data-cue-nav` attributes in the HTML, and the Notes reference regenerates itself.
- If you later tokenise more values in the HTML (wrap them in `ST:NAME_START …
  ST:NAME_END` markers), you can switch those fields from "Claude fills them" to a
  pure n8n find‑and‑replace and shrink the model's job.
